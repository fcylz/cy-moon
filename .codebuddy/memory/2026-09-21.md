## Bug 修复：留言板回复楼层顺序错乱

现象：回复的「N楼」编号没有按先后排列。

### 根因（两个函数互相叠加）
1. **楼层号取自 map 下标**，而 `cs` 是 `(p.comments||[]).filter(...)` —— 即**数组插入顺序**，不是时间顺序
2. 只有 `scheduleBoardComments`（彼回复）末尾做过一次 `sort by ts`（还是虚拟 ts）；
   `sendBoardComment`（**我**回复）push 后**压根没排**，所以它永远占着数组末尾
3. 时间轴混用：我的回复 `ts = Date.now()`（真实），彼的回复 `ts` 是 `_nextBoardTs()` 生成的**虚拟未来时间**
   → 我刚发的真实时间会被排到彼那些"未来"回复**之后**，看起来像插队到最上面

### 修复（统一两条时间轴）
- 新增 `_cmtRealTs(c) = c.arriveAt || c.ts` —— 彼的按到达时刻、我的按发送时刻，同一条真实时间轴可比
- 新增 `_commentsOf(post)`：渲染前统一 `sort(_cmtRealTs)`，**所有读取入口都走它**
  （`renderBoard` / `renderBoardDetail` / `scheduleBoardComments` 的引用池 slice(-3)）
- `sendBoardComment` push 后也按 `_cmtRealTs` 排一次（双保险，存库即有序）
- `_lastTsIn(post)` 改为取 **`Math.max(ts)`** 而不是 `cs[cs.length-1].ts`
  ← 原来我插在末尾的真实时间回复会把下一条彼回复的虚拟时间锚点**拽回过去**

### 实测（脚本验证）
- 场景：彼甲(+15s到) / 我乙(+20s) / 彼丙(+40s到)，彼两条是一次 schedule 先入库的
- 修复前：1楼甲 2楼丙 3楼乙 ✗ → 修复后：1楼甲 2楼乙 3楼丙 ✓
- 楼层号稳定：先到的不会被后到的挤动（+16s 显示 1甲2乙，+41s 仍是 1甲2乙3丙）
- 时间锚点取到最大值（丙），不再倒退

### ⚠ 记住的教训
这个 App 里**到处是双时间轴**：`ts` 可能是虚拟的（彼的内容），`arriveAt` 才是真实发生的时刻。
凡是要排「先后顺序」的地方，必须用 `arriveAt || ts`，不能用 `ts`，更不能靠数组插入顺序。

## 组字（genRecomb）本次新增的两张内置表

1. **意象 / 时间 / 处所槽位** `{i}{t}{p}`（`RECOMB_IMAGES` 20 / `RECOMB_TIMES` 14 / `RECOMB_PLACES` 16）
   + 8 条带这些槽的模板。**刻意不放进 Markov 链**（它们是名词，灌进链只会反复冒同一批词），
   走槽位每次只出一两个，像随手拈来的场景。
2. **句尾收束** `RECOMB_TAILS`（45% 概率）：`……` 写了三遍做加权 —— 因为 Markov 走到目标长度是**硬停**，
   常常断在词中间（"我在月亮里想起"），省略号接得住；只在句尾无标点时补。

实测（27 张假字卡跑 30 句）：意象命中 18/30、句尾收束 14/30、生成失败 0。

## ⚠ 发现但**尚未修**的质量问题（下次可接着做）
`_buildMarkov` 里 `idx.frags / idx.segs` 是 `seg.substr(随机位置, 随机长度)` 的**任意子串**，
会把词切碎 → 长句拼段和模板填空出来的东西带语病：
```
到很远的时候，终年不 / 时的勇气的时候 / 影子留在车站在啊。
忽然之间就长大了，忽然之间就长大了，…（同一片段重复出现）
```
根因：没有分词器，切点不看词边界。
修法候选：只在「子句开头」或「功能字之后」（的/了/在/和/就/把/被/到/着/过…）取起点，终点也尽量落在边界。
  - 不用晚于上一条 ❌（可以「早上」排在「傍晚」后面）
  - 不用避开深夜 ❌、不管现在几点 ❌
  - 不跨天 ❌
- 楼层先后永远由 `arriveAt` 决定，时刻乱序**不影响**任何排序 → 所以上面那些约束全无必要

实现就几行（`_nextBoardTs`）：`new Date(anchor)` 拿日期 → 随机抽 `BOARD_DAY_PARTS` 一段 → `setHours(段起点+随机偏移, 随机分钟)` → 返回。
**没有** `_boardSlots`、**没有** `BOARD_MIN_GAP`（都已删除，勿恢复）

### 实测（3000 次抽样）
- 日期偏离真实当日：**0 次** ✓
- 时段名越界：**0 次** ✓
- 分布均匀：凌晨16% / 清晨17% / 早上15.6% / 中午17.1% / 下午18.7% / 傍晚15.6% ✓

⚠ 副作用要记得告诉用户：删掉"晚上"后，**19 点以后统统显示「傍晚」**。
想加回就在 `BOARD_DAY_PARTS` 的傍晚后面插 `{h:19,n:"晚上"}`（源码注释里写了）。
