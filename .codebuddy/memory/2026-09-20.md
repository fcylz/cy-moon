## 已实现：方案C —— 内置离线简转繁词典
- 新增生成器产出 **`s2t-dict.js`（187KB）**，`window.S2T_DICT` 为整段字符串；index.html 用 `<script src>` 引入（放 localforage 之后、app.js 之前），**不用 fetch**，故 `file://` 直接打开也能用
- 数据来源 OpenCC（jsdelivr CDN）：STCharacters.txt 3881 单字 + STPhrases.txt 35756 词组
- **核心裁剪技巧（体积 720KB→187KB）**：对每条词组计算「逐字用单字表转换」的结果 v1，只有当 `v1 !== 词组目标值` 时才保留该词条 → 35756 条只剩 **7751 条真·消歧条目**，其余 28005 条冗余（可由单字表推导）。最终 11632 条 / maxLen=4
- 词表用**空格**分隔 key/value（而非 OpenCC 的 tab），省去 JS 字符串里的 `\t` 转义，再省几 KB
- app.js 实现：`_ensureS2T()`（懒建 Map，11632 条）+ `s2t(s)`（**长词优先最大正向匹配**，最长 4 字 → 单字 → 原样保留）
- **`S2T_OVERRIDE` 人工校正层**（放解析最后无条件覆盖，优先级最高）：`吃→吃`（原表 吃→喫 会把「吃饭」变「喫飯」，已修正）、`着→著`（单字表缺 着→著，词组覆盖不到处会漏）、`皇后/太后/影后` 固定不转（无分词时对「皇后的后」无法区分）
- `cfg.tradTransOn:true` + 设置页开关 `sw_tradTransOn` + `syncUI` 同步
- 接入点选在 `_addChatMsg`：**仅对 `sender==="opp"` 且无手写 `translation` 且非图片/表情/画作/歌曲** 的消息自动生成译文 —— 一处覆盖全部回复类型，且不污染卡片数据
- 实测：28000 字转换 5ms；10 句聊天例句全部正确
- 已知保留差异（属 OpenCC s2t 正字选择，未改）：麪(而非麵)、裏(而非裡)、爲(而非為)、着→著 已补；**不含**地区用词差异（软件→軟體 属 s2twp）
- 待观察：`台`→`臺`、`后`→`後` 在缺词组覆盖时仍会误转，用户可自行往 `S2T_OVERRIDE` 追加

## 已实现：组字（Markov B + 模板 C + 退回抽卡）
用户定版：B 主 + C 兜底 / 起止无固定 / 长度 3-30 字 / 同一 n-gram 出现上限 3 次 / 只用非歌词的字卡 / 加时间复杂度限制、失败退回原抽卡
- 代码位置：`fireReply` 之前的「══ 组字 ══」区块；入口 `genRecomb()`
- **三级降级**：`_markovSentence()` → 失败 → `_tmplSentence()` → 失败 → 返回 "" → fireReply 的 `recombined` 标志为 false → 走原抽卡逻辑
- `_buildMarkov()`：语料 = `cards.filter(!shielded && cat 未被屏蔽 && cat!=="歌词库")`，**按非汉字切成子句再建链**（跨句不能建链，否则接缝会被当成合法搭配）；产出 bi/tri/chars/frags(2-4字，模板槽位)/segs(4-10字真实片段，长句重组)
- 缓存签名 `cards.length|总字数|屏蔽分类|屏蔽卡数` —— 加「总字数」是为了编辑/替换单张卡（卡数不变）也能失效
- **关键实测教训（重要）**：
  1. 硬把单条 Markov 链走到长目标会崩坏；但也不能「多段 Markov 拼接」——实测那样 avgLen 19.6、出现 44 字胡言串，**更糟**
  2. **最终方案**：`target<=12` 走单段 `_markovWalk`；`target>12` 改用 `segs`（语料里真实存在的子句片段）重组 —— 每段语法都成立，效果最接近「组字」语义。实测 avgLen=15.4、median=16、无一超过 30、500 句 5ms
  3. 曾经修掉的 bug：模板片段长度 `1+random*3` 实为 1~3 字（注释写的 2~4），导致模板句出现「我不个」；改为 `Math.min(seg.length, 2+random*3)`
- 挂接：`fireReply` 文字分支内，`if(cfg.recombOn && Math.random()*100 < cfg.recombProb)` → 生成成功则 `text=gen; trans=""; fragments=[gen]`，跳过抽卡；`trans=""` 使其能被**自动繁体译文**接管
- 配置：`recombOn:true, recombProb:15, recombOrder:3, recombMin:3, recombMax:30, recombMaxRepeat:3, recombMaxSteps:300`
- UI：设置页 `sw_recombOn` 开关 + 「组字设置」snav 入口 → `openRecombSettings()`/`renderRecombSettings()`（含占比/链阶/长短上限/重复上限/步数上限滑杆 + 「试生成一句」预览 + 语料统计）
- 时间/联防：`budget` 对象跨 twigg年开始ichéville purge 全句共享，`maxSteps` 硬上限；`_pickRecombChar` 返回 null 即停
- 注意：若后续要加原创 preview，需 `_mkCache=null` 强制重建索引

### 2c. transProb 语义变更 —— 由「是否生成译文」改为「是否以繁体为正文」（用户确认后修正）
