# 2026-09-25

## v1.15.2 · 字卡/表情重复 + 云端表情拉不到

**重复问题确实是云同步造成的**，两个独立来源：
1. 云端导入 id = `"c"/"sk" + Date.now()`，两台设备各导入同一批 → id 不同 → `_mergeById` 当成两条，同步一轮多一份。
2. 表情 src 域名换过（raw → jsdelivr），同一张图两个地址，src 判重失效。

修复：新增 `_cardKey`(cat+正文) / `_stickerKey`(取 `/Meme/` 后路径，抹掉域名) / `_dedupeBy(list,keyFn,better)`；
`_mergeCards`/`_mergeStickers` 取代 cards/stickers 的 `_mergeById`；表情同图优先留非 raw（raw 本机不可达，
`_stickerRank`）。三处导入（云端字卡/云端表情/粘贴链接）统一判重键。
新增 `window.dedupeLib(auto)` 清历史重复，启动 1.5s 后自动跑一次（幂等，没清掉不写盘）。

**云端表情拉不到**：云端索引缓存**无 TTL** 且 `refreshCloudCards/refreshCloudStickers` 在 index.html
**没有任何调用点**（只有音乐库有刷新按钮）→ 云端新增永远进不来。
修：`CLOUD_INDEX_TTL=6h` + fetch URL 追加 `t=Date.now()` 绕过 CDN 缓存 + 两个云端库弹窗加「刷新云端」按钮
（刷新后就地重渲染）+ 弹窗补状态行（原来 `updateCloudStickerStatus` 找不到元素，状态从不显示）。

抽片段跑 10 项断言全过（跨设备去重/保留本机/域名归一/不误删/幂等）。

⭕ 经验：`_mergeByKey` 只按 id 的合并策略，对「内容来自外部导入、id 是时间戳生成」的数据源一律不够，
必须再叠一层内容键去重。

**追加（用户二报"重新拉取会叠加"）**：判重逻辑本身是对的，问题在**界面不可见** ——
云端库弹窗里已导入的项没有任何标记，刷新一次勾选状态也没了，再「全选」就重复导入。
修：已导入项标「已导入」+ 禁用勾选（整项淡化）、「全选」与分组全选都跳过已导入、
导入收尾再跑一次 `_dedupeBy` 兜底。
⭕ 教训：**判重只写进逻辑不够，用户操作界面必须能看出"哪些已经有了"**，否则用户会重复操作。

云端 `meme.json` 实测：78 条，`url` 一律 `Meme/images/...` 相对路径，云端内部无重复 → 重复只在本地侧。
`word.json`：1521 条，单组「自定义回复」，同样无重复。

**v1.15.4（用户三问「已经重复的呢」）**：新增手动清理入口
**设置 → 数据 → 存储管理 → 清理重复内容** → `cleanDupes()`：先 `countDupes()` 报数量 + 说明判重标准，
confirm 后才 `dedupeLib(false)`。自动清理仍在启动 1.5s 跑（静默优先）。

**v1.15.4（用户四问「重复的表情，聊天里彼用过的还能对应上吗」）**：
⛔ 去重**不能只删多余那条** —— 聊天存的是 `stickerId`（引用锚点），删了老消息就永久变占位图
（v1.14.x 删 painterSeed/imgId/stickerId 那个坑的**第三次**翻版）。
✅ 做法：`_dedupeStickersWithMap()` 返回「被合并掉 → 保留」的 id 映射，`_remapStickerIds()` 改指
（覆盖 chats / quote / msgs+comments），映射存 `cfg.stickerAlias` 兜底，`_findSticker()` 统一别名回退
（resolveStickerSrc / sendSticker / toggleStickerShield / _cacheStickerThumbnailById 都改走它）。
keep 优先级：非 raw > **有聊天引用的** > 靠前。
⭕ 通用教训：**任何"删重复/合并条目"的操作，先查这个 id 有没有被别处当引用锚点持有。**
